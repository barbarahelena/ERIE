# ERIE fructose kinetics

Pharmacokinetic (PK) modeling of plasma fructose kinetics from the ERIE trial's fructose challenge tests (FCT).

## Project layout

Scripts are numbered in the order of the pipeline. Results sit in one folder per stage.

```
data/                         raw data (untouched by any script)
data/processed/               cleaned, tidy data (generated by 01_clean_data.R)
scripts/
  01_clean_data.R             raw -> tidy data cleaning, ERIE-specific
  02_fit_shared_kel.R         fructose fitted with one kel per subject across both visits (conditional on a stable kel), wave structure per visit included
  03_diet_summary_shared_kel.R   diet-arm tables and plots for the shared-kel fit
  04_simulate_ka_kel_recovery.R  simulation of the study design with independent fits
  05_simulate_shared_kel.R    the same simulation with the shared-kel fit
  06_plot_simulations.R       supplementary figure comparing the two simulations
  07_fit_13C6.R               13C6 tracer fitted with ka and kel held at the shared-kel 12C estimates
  08_diet_summary_13C6.R      diet-arm tables and plots for the 13C6 fit
  assets/
    pk_curves.R               generic PK compartment models (recyclable)
    pk_fit.R                  generic multi-start optimization engine (recyclable)
    pk_diagnostics.R          generic fit diagnostics (recyclable)
    pk_stats.R                paired Wilcoxon / linear mixed model helpers
    pred_13C6.R               13C6 prediction per mechanism, shared by 07 and 08 (ERIE-specific)
    tests.R                   regression tests for the files above
    replot_only.R             re-draws the plots of the archived joint model
  archive/                    git-ignored: earlier setups (joint 12C/13C6 model, independent fructose fit, ka/kel grid profile and identified quantities)
results/                      git-ignored
  01_shared_kel/              output of 02 and 03
  02_diagnostics_ka_kel/      output of 04 to 06
  03_13C6_fixed_rates/        output of 07 and 08
  archive/                    output of the archived setups (not used by the pipeline)
docs/
  methods.md                  methods text for the manuscript
  pk-model.md                 model specification, rationale, and caveats (joint model)
  problems-and-fixes.md       history of problems found and how each was fixed
  archive/                    superseded docs (ka/kel identifiability under the former kel bounds)
```

The shared-kel fit uses only `data/processed/`: it chooses each visit's mechanism (`single_wave` or `two_wave`) and fits the wave parameters itself. Nothing in the pipeline reads from `results/archive/`.

The three `pk_*.R` files in `scripts/assets/` are written to be project-agnostic - they know about doses, rate constants, and volumes of distribution, but nothing about fructose or ERIE specifically. Copy them into another PK modeling project as a starting point.

## Running the pipeline

Dependencies are managed with [pixi](https://pixi.sh) (see `pixi.toml`). The task names carry the number of their script:

```
pixi run 01-clean-data               # data/ -> data/processed/
pixi run 02-fit-shared-kel           # data/processed/ -> results/01_shared_kel/
pixi run 03-diet-summary-shared-kel  # results/01_shared_kel/ -> diet-arm plots and statistics
pixi run pipeline                    # 01, 02 and 03 in order
pixi run 04-simulate-ka-kel          # simulations (04 and 05 take hours; noise level from the 02 output)
pixi run 05-simulate-shared-kel
pixi run 06-plot-simulations         # figure from the saved 04 and 05 replicates
pixi run 07-fit-13C6                 # results/01_shared_kel/ -> results/03_13C6_fixed_rates/
pixi run 08-diet-summary-13C6        # results/03_13C6_fixed_rates/ -> diet-arm plots and statistics
pixi run test-engine                 # regression tests for the generic PK engine
```

The simulations run in parallel; two environment variables help while iterating:

```
ERIE_SIM_REPS=10 pixi run 04-simulate-ka-kel   # replicates per scenario (default 50)
ERIE_N_CORES=4 pixi run 02-fit-shared-kel      # cap the number of cores
```

## Start here

Comments in the scripts say what the code does; the reasoning and the evidence behind it live in `docs/`.

- **What the model is and what it can/can't tell you:** `docs/pk-model.md` - in particular, the bioavailability estimates (`F`) are conditional on an assumed volume of distribution and should not be reported as precise absolute numbers; see the identifiability discussion there before using them in any write-up.
- **Why the model looks the way it does:** `docs/problems-and-fixes.md` - the problems found during development and the fix for each.
