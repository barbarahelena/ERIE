# ERIE fructose kinetics

Pharmacokinetic (PK) modeling of plasma fructose kinetics from the ERIE trial's fructose challenge tests (FCT).

## Project layout

```
data/                    raw data (untouched by any script)
data/processed/          cleaned, tidy data (generated by 01_clean_data.R)
scripts/
  01_clean_data.R        raw -> tidy data cleaning, ERIE-specific
  joint_12C_13C6/        12C and 13C6 fitted jointly
    02_fit_erie_model.R    ERIE-specific model wiring + fitting, uses assets/
    03_diet_summary.R      diet-arm comparison of the fitted parameters
  fructose_independent/  fructose fitted on its own (no 13C6)
    02_fit_erie_model_fructose_independent.R
    03_diet_summary_fructose_independent.R
  fructose_shared_kel/   one kel per subject across both visits (conditional analysis)
    02_fit_erie_model_fructose_shared_kel.R
    03_diet_summary_fructose_shared_kel.R
  diagnostics_ka_kel/    ka/kel identifiability: profile, identified quantities, simulations
    04_profile_ka_kel.R .. 07_simulate_shared_kel.R
  assets/
    pk_curves.R          generic PK compartment models (recyclable)
    pk_fit.R             generic multi-start optimization engine (recyclable)
    pk_diagnostics.R     generic fit diagnostics (recyclable)
    tests.R              regression tests for the three files above
    replot_only.R        re-draws the per-subject plots without refitting
results/                 git-ignored; one folder per model setup:
  joint_12C_13C6/        02, 03 (12C and 13C6 fitted jointly)
  fructose_independent/  02, 03 (fructose fitted on its own)
  fructose_shared_kel/   02, 03 (one kel per subject across visits)
  diagnostics_ka_kel/    04 to 07
docs/
  pk-model.md            model specification, rationale, and caveats
  ka-kel-identifiability.md  why ka and kel cannot be separated, and the tests run
  problems-and-fixes.md  history of problems found and how each was fixed
```

The three `pk_*.R` files in `scripts/assets/` are written to be project-agnostic - they know about doses, rate constants, and volumes of distribution, but nothing about fructose or ERIE specifically. Copy them into another PK modeling project as a starting point; only `02_fit_erie_model.R` (and the cleaning script) should need to change.

## Running the pipeline

Dependencies are managed with [pixi](https://pixi.sh) (see `pixi.toml`):

```
pixi run clean-data    # data/ -> data/processed/
pixi run fit-model     # data/processed/ -> results/joint_12C_13C6/
pixi run diet-summary  # results/joint_12C_13C6/ -> diet-arm plots and statistics
pixi run pipeline-joint # clean-data, fit-model, diet-summary (joint 12C/13C6 model only)
pixi run pipeline      # joint model, then the independent and shared-kel setups (fits and diet summaries)
pixi run test-engine   # regression tests for the generic PK engine
```

The model fit takes several minutes (parallelized across cores - each of the 68 subject x visit fits involves numerical ODE integration and multi-start optimization; see `docs/pk-model.md`). Two environment variables help while iterating:

```
ERIE_TEST_SUBJECTS="ER01,ER02,ER03" pixi run fit-model   # fit only these subjects
ERIE_N_CORES=4 pixi run fit-model                        # cap the number of cores
```

`scripts/assets/replot_only.R` is not part of the pipeline: it re-draws `results/joint_12C_13C6/plots_individual/` from an existing `results/joint_12C_13C6/fit_results.csv`, to check a plotting-only change without refitting.

## Start here

Comments in the scripts say what the code does; the reasoning and the evidence behind it live in `docs/`.

- **What the model is and what it can/can't tell you:** `docs/pk-model.md` - in particular, the bioavailability estimates (`F`) are conditional on an assumed volume of distribution and should not be reported as precise absolute numbers; see the identifiability discussion there before using them in any write-up.
- **Why the model looks the way it does:** `docs/problems-and-fixes.md` - the problems found during development and the fix for each.
