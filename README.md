# ERIE fructose kinetics

Pharmacokinetic (PK) modeling of plasma fructose kinetics from the ERIE trial's fructose challenge tests (FCT).

## Project layout

Scripts are numbered in the order of the pipeline. Results sit in one folder per stage.

```
data/                         raw data (untouched by any script)
data/processed/               cleaned, tidy data (generated by 01_clean_data.R)
scripts/
  01_clean_data.R             raw -> tidy data cleaning, ERIE-specific
  02_fit_shared_kel.R         12C fitted with one kel per subject across both visits (conditional on a stable kel), wave structure per visit included
  03_diet_summary_shared_kel.R   diet-arm tables and plots for the shared-kel fit
  04_fit_13C6.R               13C6 tracer fitted with ka and kel held at the shared-kel 12C estimates
  05_diet_summary_13C6.R      diet-arm tables and plots for the 13C6 fit
  simulations/
    01_ka_kel_recovery.R      simulation of the study design with each visit fitted alone
    02_shared_kel.R           the same simulation with a simplified (single-wave) shared-kel fit
    03_plot.R                 supplementary figure comparing 01 and 02
    04_structure_selection.R  the full 02 procedure on simulated single- and two-wave curves, comparing structure rules
    05_plot_structure_examples.R  example simulated curves for each outcome of the structure choice
  assets/                     code the numbered scripts load (see "Where things live" below)
  archive/                    git-ignored: earlier setups (joint 12C/13C6 model, independent fructose fit, ka/kel grid profile and identified quantities)
results/                      git-ignored
  01_shared_kel/              output of 02 and 03
  02_diagnostics_ka_kel/      output of the simulations
  03_13C6_fixed_rates/        output of 04 and 05
  archive/                    output of the archived setups, and 01/03 under the gated and always_try rules (not used by the pipeline)
docs/
  methods.md                  methods text for the manuscript
  pk-model.md                 model specification, rationale, and caveats
  problems-and-fixes.md       history of problems found and how each was fixed
  archive/                    superseded docs (ka/kel identifiability under the former kel bounds)
```

## Where things live

The numbered scripts read data, run a model and write tables and plots. The models and the code they share are in `scripts/assets/`. Each asset file loads the asset files it needs, so a script only loads the model it runs.

| File | Contents | Loaded by |
|---|---|---|
| `pk_equations.R` | PK equations: Bateman curve, lagged second dose, delayed release | the model files, 03, simulations 01 and 02 |
| `optimizer.R` | `build_objective()`, `fit_multistart()`, starting seeds, penalty settings (`MIN_TMAX`, `CMAX_TOL`, ...), `r_squared()`, `aic_rss()` | the model files, simulations 01 and 02 |
| `curve_checks.R` | checks on the raw observations for a second wave or an onset lag | the model files |
| `model_12C.R` | the 12C model: bounds and settings, `fit_alone()` (stage 1), `fit_shared()` (stage 2) | 02, simulation 04 |
| `model_13C6.R` | the 13C6 model: bounds, `pred_13C6()`, `fit_13C6()` | 04, 05 |
| `stats.R` | linear mixed model for the diet summaries | 03, 05 |
| `theme_publication.R` | ggplot theme | scripts that plot |
| `tests.R` | regression tests for the files above | `pixi run test-engine` |

The shared-kel fit uses only `data/processed/` and runs in two stages: stage 1 fits each visit alone and chooses its structure (`single_wave` or `two_wave`), and stage 2 fits one `kel` per subject with that structure. `STRUCTURE_RULE` in `model_12C.R` sets how stage 1 chooses (`tail_limit`, the default; `gated`; `always_try`; see "Choosing between single_wave and two_wave" in `docs/pk-model.md`). Nothing in the pipeline reads from `results/archive/`.

## Running the pipeline

Dependencies are managed with [pixi](https://pixi.sh) (see `pixi.toml`). The task names carry the number of their script:

```
pixi run 01-clean-data               # data/ -> data/processed/
pixi run 02-fit-shared-kel           # data/processed/ -> results/01_shared_kel/
pixi run 03-diet-summary-shared-kel  # results/01_shared_kel/ -> diet-arm plots and statistics
pixi run pipeline                    # 01, 02 and 03 in order
pixi run 04-fit-13C6                 # results/01_shared_kel/ -> results/03_13C6_fixed_rates/
pixi run 05-diet-summary-13C6        # results/03_13C6_fixed_rates/ -> diet-arm plots and statistics
pixi run sim-01-ka-kel-recovery      # simulations (01, 02 and 04 take hours; noise level from the 02 output)
pixi run sim-02-shared-kel
pixi run sim-03-plot                 # figure from the saved replicates of simulations 01 and 02
pixi run sim-04-structure-selection
pixi run sim-05-plot-structure-examples  # about 3 min
pixi run test-engine                 # regression tests for the assets
```

The simulations run in parallel; two environment variables help while iterating:

```
ERIE_SIM_REPS=10 pixi run sim-01-ka-kel-recovery   # replicates per scenario (default 50)
ERIE_N_CORES=4 pixi run 02-fit-shared-kel      # cap the number of cores
```

## Start here

Comments in the scripts say what the code does; the reasoning and the evidence behind it live in `docs/`.

- **What the model is and what it can/can't tell you:** `docs/pk-model.md` - in particular, the bioavailability estimates (`F`) are conditional on an assumed volume of distribution and should not be reported as precise absolute numbers; see the identifiability discussion there before using them in any write-up.
- **Why the model looks the way it does:** `docs/problems-and-fixes.md` - the problems found during development and the fix for each.
